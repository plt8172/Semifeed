# 릴스 대본·장면 가이드

기술 원리 설명 릴스를 만들 때 대본과 장면이 지켜야 할 규칙이에요. `reels/AGENTS.md`의 2~4단계에서 이 문서를 기준으로 쓰고 점검해요.
규칙은 실제 시안에 대한 피드백에서 나왔어요. 근거는 맨 아래 "피드백 기록"에 있어요.

## 시청자와 형식

- 시청자: 공학 배경이 없는 일반인(고등학생~직장인). 피드를 넘기다 멈추게 만들어야 해요.
- 형식: 인스타그램 릴스, 세로 1080×1920, 한국어 나레이션과 자막, 40~60초, 장면 5~8개.
- 시리즈 범위: 전자·반도체·통신·제어·신호·소자·컴퓨터.

## 대본 규칙

1. **훅은 첫 3초 안에.** 시청자의 일상과 이어진 의외의 사실 한 문장으로 시작해요. ("전화 속 목소리는 상대 목소리가 아니다")
2. **복잡한 과정은 3~4단계로 압축해요.** 강의 순서를 따르지 말고, 시청자가 "왜?"라고 물을 순서로 짜요.
3. **각 단계 안에서는 충분히 설명해요.** 배경지식이 없는 사람이 따라오도록 비유나 일상 예시를 하나씩 붙여요. 압축은 단계 수를 줄이는 것이지 설명을 빼는 게 아니에요.
4. **개념이 먼저고, 숫자와 용어는 그다음이에요.** "비트", "kbps", "샘플링" 같은 말은 무엇인지 먼저 보여 준 뒤에 꺼내요. 숫자로 시작하지 않아요.
5. **숫자는 시청자가 아는 단위로 바꿔요.** "64 kbps"보다 "1초에 0과 1 6만 4천 칸"이 더 잘 와닿아요. 비교할 때는 앞에서 정의한 단위를 계속 써요.
6. **증명은 끝 쪽에 둬요.** 실제로 들려주거나 보여 주는 데모(코덱 통과 음성, 실측 파형)는 원리를 이해한 다음에 나와야 의미가 생겨요.
7. **틀린 말은 쓰지 않아요.** 단순화는 괜찮지만 거짓은 안 돼요. 단순화한 부분은 `script.md`에 따로 적어요.
8. **나레이션은 말하듯이 써요.** 한 문장은 25자 안팎으로 쓰고, 쉼표로 숨 쉴 곳을 만들어요. 오프라인 TTS를 쓸 때는 숫자를 한글로 풀어 써요("팔천 번"). 화면 자막(`caption`)에는 숫자를 그대로 써도 돼요.

## 장면 규칙

1. **장면 하나에는 메시지 하나만 둬요.** 제목 한 줄과 그림 하나, 그리고 자동으로 붙는 자막만 넣어요. 제목과 자막이 같은 말을 반복하지 않게 해요.
2. **1.5~2초마다 무언가 움직이게 해요.** 등장(`R.pop`), 그리기, 확대, 숫자 세기처럼요. 나레이션이 그 단어를 말하는 순간(`R.at(0.4)`)에 맞춰요.
3. **진짜 데이터를 써요.** 실제 음성 파형(`R.clip`), 실제 코덱 결과(`reel.py codec`), 실제 단위와 수치를 써요. 가짜 장식 그래프는 넣지 않아요.
4. **안전 영역을 지켜요.** 중요한 내용은 `.safe` 안(위 220px, 아래 380px, 오른쪽 140px 제외)에 둬요. 자막은 아래쪽 420px 위에 자동으로 떠요.
5. **글자 크기는 제목 64~96px, 본문 40px 이상으로 해요.** 휴대폰에서 읽혀야 해요. 원문자(①②③)는 폰트에 없을 수 있으니 "1 ·"처럼 써요.
6. **움직임은 시간 t로만 계산해요.** CSS animation, transition, setTimeout, Date.now()는 쓰지 않아요. 렌더러가 프레임마다 `seek(t)`를 불러 캡처하기 때문이에요.
7. **색은 kit 토큰을 써요.** `--a`(주 강조), `--b`(보조), `--c`(대비), `--muted`, `--dim`. 한 장면에 강조색은 두 개까지만 써요.

## 자체 점검 (build 전에 하나씩 확인)

- [ ] 첫 장면만 봐도 "어? 왜?"가 생기는가
- [ ] 단계가 3~4개인가, 각 단계에 비유나 예시가 하나씩 있는가
- [ ] 처음 나오는 용어·숫자마다 그 앞에 설명이 있는가
- [ ] 데모나 증명이 원리 설명 뒤에 나오는가
- [ ] 기술적으로 틀린 문장이 없는가, 단순화 목록을 적었는가
- [ ] `preview.png`에서 글자가 겹치거나 잘리거나, 화면이 비어 있는 장면이 없는가
