# 보코딩

- 주제: 휴대폰 통화가 목소리를 보내는 방법, 보코딩(분석해서 숫자로 보내고, 받는 쪽이 다시 합성)
- 알게 될 것: 통화 속 목소리는 보낸 소리 그대로가 아니라, 받은 숫자로 내 폰이 다시 만든 소리다
- 형식: 챕터형 (훅 → 문제 → 단서 → 원리 → 해법 → 증명)

## 근거 자료
- KAIST EE321 통신공학 L8 Source coding, 슬라이드 9~11 (PCM, ADPCM, Vocoding: Analysis and Synthesis)
- 목소리는 약 20ms 동안 특성이 거의 안 변함 → 20ms 조각마다 분석해 정보만 비트로 보내고, 수신 측이 합성
- 휴대폰 보코더 예: QCELP, CELP, AMR-NB (12.2~4.75 kbps). 슬라이드의 "ARM-NB"는 AMR-NB 오타
- 음성 생성 모델(소스-필터): 성대의 주기적 떨림(음높이) × 입·목의 공명(포먼트) = 모음

## 틀리면 안 되는 수치
- 전화 PCM: 8,000번/초 × 8비트 = 64,000 bit/s. 0.006초 창에는 측정 48번
- 20ms 조각 = 1초에 50번
- GSM(2G) 13 kbps = 64 kbps의 약 1/5. Codec2 700C 700 bit/s = 약 1/90 (64000 ÷ 700 = 91.4)
- 실제 CELP는 필터 계수(LSF), 피치 지연, 코드북 번호, 이득을 보낸다. "번호 하나만"은 틀린 단순화
- 모음 포먼트(성인 남성 어림값): '아' 800·1200·2500 Hz, '이' 280·2250·2900 Hz. 성대 떨림 120 Hz

## 데모 (진짜 데이터)
- `audio/buzz.wav`, `a.wav`, `ai.wav`: 성대 떨림만 / '아' 입 모양을 씌움 / 입 모양만 '아'→'이'로. `make_audio.py`가 화면과 같은 식으로 합성
- `audio/A·B·C.wav`: 같은 문장("내 목소리 잘 들려?")을 PCM 64k · GSM 13k · Codec2 700bps로 보냈다 복원 (`reel.py codec`)
- 확인: `reel.py listen`으로 받아 적으면 a→"아", ai→"아~이~", A·B·C 모두 "내 목소리 잘 들…"로 들린다 (2026-11-12)
