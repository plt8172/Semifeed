# 대본: 보코딩

형식: 챕터형. 훅: "통화 속 목소리는 상대방 목소리가 아니다" (매일 하는 일 + 의외의 사실)

훅 후보
1. "통화 속 목소리는 상대방 목소리가 아니다" ← 선택. 누구나 매일 겪는 일이고, 한 문장으로 "어? 왜?"가 생긴다
2. "전화는 목소리의 90분의 1만 보낸다": 숫자로 시작해서 와닿지 않음
3. "전화기는 사실 악기다": 비유가 먼저 나와 무슨 말인지 모름

| 장 | 나레이션 | 화면 (하나의 무대가 이어진다) |
| --- | --- | --- |
| 훅 | 통화할 때 들리는 목소리. 그거, 상대방 목소리 아니에요. 내 폰이 방금 만들어 낸 소리예요. | 폰 속에 실제 음성 파형. "만들어 낸"에서 폰이 파형을 주황으로 다시 그린다 |
| 01 문제 | 소리는 공기의 떨림이에요. 그대로 보내려면, 이 떨림을 1초에 8,000번 재야 해요. 0과 1로 적으면, 64,000칸이에요. 모두가 동시에 통화하기엔 너무 많아요. | 폰을 뚫고 파형이 화면 가득. 0.006초로 확대 → 측정 점 48개가 찍히고 8,000까지 센다 → 점의 실제 값이 0과 1로 적힌다 → 64,000 |
| 02 단서 | 그런데 '아' 소리를 확대해 보면, 같은 모양이 계속 반복돼요. | '아' 파형이 그려지고, 첫 주기 조각이 옆 주기로 옮겨 가며 정확히 겹친다 |
| 03 원리 | 성대가 일정하게 떨기 때문이에요. 성대 소리만 들으면 이래요. (성대음) 여기에 입 모양이 더해지면, ('아') 입 모양만 바꾸면, ('아→이') | 주기 경계선이 위로 올라가 성대 떨림이 된다. 입 모양 곡선이 자라면 아래 소리가 '아'가 되고, 곡선이 바뀌면 '이'가 된다. 소리와 그림이 같은 식 |
| 04 해법 | 그래서 폰은 소리를 보내지 않아요. 얼마나 빨리 떠는지, 입 모양이 어떤지. 이 숫자 몇 개만, 1초에 50번 보내요. 받는 폰은 그 숫자로 목소리를 다시 만들어요. | 파형이 흐려지고, 떨림과 곡선에 숫자가 붙는다. 숫자만 묶음이 되어 내려가고, 받는 폰이 조각마다 파형을 다시 그린다 |
| 05 증명 | 데이터를 전부 보낸 소리. (A) 5분의 1만 보낸 소리. (B) 90분의 1만 보낸 소리. (C) | 같은 문장 세 줄. 데이터 양 막대가 64,000 → 13,000 → 700으로 줄어든다 |
| 맺음 | 90분의 1인데도, 알아들을 수 있어요. 이 기술이 보코딩이에요. 오늘 통화한 그 목소리도, 폰이 만든 소리였어요. | "보코딩" + 첫 화면의 폰 (처음으로 이어진다) |

## 단순화한 부분
- 실제 보코더(CELP 계열)는 음높이·입 모양(필터 계수) 외에 세기와 코드북 번호도 보낸다. 화면의 "빠르기, 입 모양 숫자 둘"은 대표값이다
- 입 모양은 실제로 숫자 10개쯤(필터 계수)으로 보낸다. 화면은 공명 봉우리 두 개의 위치로 보여 준다
- B(GSM)는 RPE-LTP, C(Codec2)는 정현파 계열 보코더로, 요즘 통화의 AMR·EVS(CELP)와 방식이 조금 다르다. "분석해서 보내고 다시 합성한다"는 점은 같다
- 요즘 HD 통화는 1초에 16,000번 잰다. 8,000번은 기본 통화 기준이다
- 받는 폰의 화면은 20ms 조각이 실제보다 훨씬 느리게 도착하는 것으로 그렸다 (화면에 표시)
