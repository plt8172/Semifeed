# 타이머 인터럽트

- 주제: CPU 코어 하나가 앱 여러 개를 같이 돌리는 방법, 타이머 인터럽트
- 알게 될 것: 앱끼리 알아서 순서를 넘기게 두면 한 앱이 CPU를 붙잡을 수 있어서, 칩 안의 타이머가 정해진 시간마다 CPU를 멈춰 세우고 다음 차례로 넘긴다. 안드로이드 폰은 이걸 1초에 250번 한다
- 형식: 실험형 (훅 → 문제 → 실험: 타이머 없음 → 원리 → 실험: 1초에 10번, 250번). 결과를 소리로 들려줄 수 있어서 실험형으로 했다
- 사용자가 고른 주제는 "타이머 인터럽트"였고, 인터럽트 전체는 60초에 너무 넓어서 "앱 여러 개가 어떻게 같이 도나" 한 질문으로 좁혔다 (2026-11-13)

## 근거 자료
- Android GKI 커널 설정 `arch/arm64/configs/gki_defconfig` (android14-6.1, android15-6.6, android16-6.12 브랜치, GitHub 미러 `aosp-mirror/kernel_common`에서 확인): `CONFIG_HZ` 줄이 없고 `CONFIG_NO_HZ=y`, `CONFIG_PREEMPT=y`
- 같은 커널의 `kernel/Kconfig.hz` ("Timer Interrupt Frequency Configuration"): `default HZ_250`. arm64 Kconfig가 이 파일을 불러온다. 그래서 GKI 폰의 타이머 인터럽트는 1초에 250번
- source.android.com: "Beginning with Android 12, devices shipping with kernel version 5.10 or higher must ship with the GKI kernel." 제조사는 GKI의 공통 커널 설정을 바꿀 수 없다
- 선점형 멀티태스킹: 타이머 인터럽트가 오면 커널이 지금 돌던 작업을 멈추고 다음 작업으로 바꿀 수 있다. 협력형(앱이 스스로 양보)은 한 앱이 양보하지 않으면 전체가 멈춘다

## 틀리면 안 되는 수치
- 1초에 250번 = 0.004초(4ms)마다. GKI 커널을 쓰는 폰(안드로이드 12 이후 출시, 커널 5.10 이상) 기준
- 아이폰(XNU)은 방식이 달라서 영상에서 말하지 않는다. 마지막 줄도 250이라는 숫자를 다시 말하지 않는다
- NO_HZ: 할 일이 없는 코어는 타이머를 멈춰 전기를 아낀다. "250번"은 일하는 코어 기준이다
- 코어 수, 프로세스 수는 기기마다 달라 말하지 않는다

## 데모 (진짜 데이터)
- `make_audio.py`: 코어 하나에서 음악 앱(0.04초 분량의 소리를 0.002초 동안 만들어 두고 양보, 절반 남으면 다시 CPU를 원함)과 무거운 앱(양보하지 않음)을 0.5ms 단위로 돌린다. 만들어 둔 소리가 남아 있을 때만 멜로디가 들리게 해서, 들리는 소리가 시뮬레이션 결과 그 자체다
- `audio/r1.wav`: 타이머 없음, 1.3초에 무거운 앱을 켠다 → 1.34초쯤부터 소리가 멈춘다 (소리 나는 비율 0.67)
- `audio/r2.wav`: 0.1초마다 멈춰 세움 → 0.1초마다 0.06초씩 끊긴다 (0.40)
- `audio/r3.wav`: 0.004초마다 → 끊기지 않는다 (1.00)
- `stage.html`은 같은 시뮬레이션을 JS로 다시 돌려 그리고, 들리는 소리 줄은 이 wav 샘플을 그대로 그린다
